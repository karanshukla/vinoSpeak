# CLAUDE.md

vinoSpeak: Kokoro-82M INT8 text-to-speech on OpenVINO GenAI, CLI plus a small
importable API. Sibling of vinoWhisper and vinoPop (it may be absorbed into
vinoPop), and it follows their conventions: `uv run poe check`, ruff + mypy,
conventional commits, CI actions pinned to a commit SHA.

## Layout

```
vino_speak/
  tts.py      Synthesizer (loaded pipeline, thread-safe; stream(), speak()) and the
              one-shot synthesize() / speak()
  text.py     chunks(): first sentence alone, then chunks that at most double
  playback.py Speech: raw float32 into one pw-play/paplay/aplay process, stop()
  model.py    cache dir, pinned download, verify(); no OpenVINO import
  cli.py      argparse front end for vinospeak
  doctor.py   vinospeak-doctor: packages, devices, ovfetch notes, model pin check
  ovfetch.py  `ovfetch detect` read into notes (advisory, never a FAIL)
  model_pins.json   generated by scripts/update_pins.py, do not edit by hand
scripts/update_pins.py
```

`import vino_speak` must stay light: no OpenVINO, numpy or huggingface_hub at
import time (vinoPop defers heavy imports). `tests/test_tts.py` fakes all three.

## Commands

```bash
uv sync --locked --only-group dev             # what CI installs
.venv/bin/python -m pytest --cov              # CI's floor is --cov-fail-under in ci.yml
uv run poe check                              # ruff, format --check, mypy (strict), pytest
```

## Things that are easy to get wrong

- **OpenVINO is pinned exactly** (`openvino==2026.4.1`, `openvino-genai==2026.4.1.0`),
  matching vinoPop's `requirements-ai.txt` and vinoWhisper's `uv.lock`. Two
  programs on one NPU must not run different releases. Bump all three together.
- **ovfetch is advisory.** vinoSpeak uses OpenVINO GenAI from pip, not ONNX
  Runtime, so it never runs `ovfetch install`. The doctor runs `ovfetch detect`
  when it is on `PATH`, and its bounds are pessimistic on purpose: nothing it
  says is a FAIL. See vinoWhisper's `docs/architecture.md` for why.
- **The NPU compiler is the exception** (ovfetch 0.6.0, 2026-10-24). Fedora's
  1.32.0 driver rpm ships none; `ovfetch npu install` puts Intel's in
  `~/.local/lib/ovfetch-npu`. `ovfetch.preload()` dlopens each line of that
  prefix's `ovfetch-preload.txt` with `RTLD_GLOBAL` before the first
  `Core()`/pipeline (`Synthesizer.__init__`, `doctor._devices`), in the file's
  order (a driver before the Level Zero loader crashed, per ovfetch's README).
  Fatal only on the NPU. `tests/conftest.py` disables the real preload for every
  test, so nothing dlopens a developer's prefix. Same code as vinoWhisper's.
- **`ensure_model(trusted=True)`** (what `--model-dir` sets) skips the pin check
  for a directory that already holds the model files; the default cache dir is
  always checked. An empty `--model-dir` still downloads the pinned model.
- **The model is pinned to a revision plus per-file sha256.** Re-pin only with
  `scripts/update_pins.py` and read the diff.
- The NPU compile takes seconds; `Synthesizer` exists so callers pay it once.
  The GUI keeps one loaded in `vinospeak --serve` (`serve.py`, a private
  JSON-lines protocol), and every pipeline gets `CACHE_DIR` (`ov-cache/` beside
  the model) so a new process can skip the compile.

## Testing without an NPU

The linuxlab VM has none: `--device CPU` runs the real pipeline (1.9 s of audio
in ~14 s including the first download). That proves the CPU path, the pins and
the WAV output. It proves nothing about NPU compile behaviour, latency, or what
`ovfetch detect` says on real hardware; the ovfetch notes are tested against
JSON captured from the Wildcat Lake laptop (2026-09-28).
